# Tracer Study: program–job alignment

Tracer Responses, Program-Job Alignment, and Employment Reports show current profile pictures, names, and emails. The Employment History modal also shows the selected alumnus's picture. Profiles are matched using the authenticated account ID (string/ObjectId compatible), including when historical responses share the same email text. Only name and photo are projected from the directory; personal/internal fields are not returned. Missing or broken photos use the shared initials fallback. Name is included in response search and CSV export.

The default admin view at `/admin/tracer` displays current tracer responses with summary cards above the table. Program–job alignment and employment reports remain tabs on the same page; alignment is directly available at `/admin/tracer?view=alignment`.

Employed and self-employed respondents provide employer/business, position/line of work, `jobAlignment` (`directly_related`, `partly_related`, `unrelated`, `unsure`), and `alignmentExplanation` (main duties and relationship to their program, max 1000 characters). These questions apply to every graduation program. Classification is self-reported; titles and courses are never automatically matched. Non-working statuses clear alignment fields; old responses have Not reported alignment.

Every successful submission atomically appends a server-dated snapshot to `tracer_responses.responseHistory` and updates the latest fields used by the alumni form. The first update to a legacy response also preserves its old observation. No historical work is fabricated from current employment. Reading ordinary responses excludes the history array.

The admin response list joins each response to its current auth account. Responses for deleted, disabled or missing accounts are excluded. If legacy documents use both string and ObjectId references to the same account, the list returns its latest response once; counts, filters, pagination and CSV use that same list. Distinct active accounts are not merged merely because their historical email text matches. The general response list continues to include all active roles permitted to submit the form, while program alignment remains alumni-only. Own-form prefill selects the latest account response deterministically.

Admin **Tracer Study > Tracer Responses** has Tracing year and Tracing quarter filters. `GET /api/tracer?year=2026&quarter=4` selects the latest recorded observation per account within that Philippine calendar period, including historical snapshots. Either filter accepts `all` independently. Q1 is Jan–Mar, Q2 Apr–Jun, Q3 Jul–Sep, and Q4 Oct–Dec in Asia/Manila. Tracing year is separate from graduation batch. Responses still use the existing `data` array, with available tracing years in `periods.years`. The table, period summaries, status/search filters, pagination, and CSV use the selected period. URL parameters preserve the selection on reload. Unknown dates remain available under All periods but do not enter a specific year or quarter. Missing historical fields are left empty rather than filled from a newer response. This filter applies to Tracer Responses; the alignment and employment reports retain their existing report-specific controls.

Historical response documents and observations are preserved, not deleted or reassigned. Alignment reads every eligible alumni observation before applying its existing per-account/program/batch follow-up rules; collapsing the current response list does not erase earlier follow-up evidence.

`GET /api/tracer/alignment` requires an admin session and considers active accounts whose current authoritative role is alumni. It supports `followUp` (default `3-5`, also `0-2`, `6+`, `all`), exact `program` and `batch`, `alignment`, and text `query`. All filters apply to summaries and exported rows. Programs and batches are discovered from the recorded data.

Follow-up years are the Manila calendar year of submission minus graduation year. This is an estimate from the graduation year, not exact graduation anniversaries. The report selects the latest observation within the selected window per alumnus/program/batch. A response from year one does not become year-four evidence as time passes. All periods selects the latest observation. Missing or invalid dates cannot enter a specific follow-up window.

Direct alignment rate = directly related / (directly related + partly related + unrelated). Related-work rate includes directly and partly related in the numerator. Not sure, Not reported, and non-working answers are shown separately and excluded from the denominator. No assessed answers displays N/A instead of a misleading 0%.
